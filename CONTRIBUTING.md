# Contributing

1. Start from the public README and governance files; use the controlled canon
   for any decision-grade change.
2. Link every material change to a source or decision.
3. Use a branch or pull request for changes to canon, public copy, prompts,
   website components or governance.
4. Keep secrets and restricted information out of the repository.
5. Run the production build before requesting review.
6. List every downstream platform that needs propagation.

Commit messages should start with the affected lane, for example:
`Health: refine flagship status copy` or `Brand: refine portfolio card states`.
